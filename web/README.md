# Ringout 숲 웹 시제품

숲 키우기 2~4단계: React·TypeScript·Vite·Three.js 기반의 3D 검토 화면과 앱용 숲 UI입니다.
개발용 미리보기는 샘플 데이터를 사용하고, 앱 전용 `?view=app` 화면은 네이티브 브릿지를 통해 Room의 실제 상태를 읽고 저장합니다.

## 실행

Node.js 22.12 이상을 사용합니다. 저장소의 `web` 디렉터리에서 실행합니다.

```sh
npm ci
npm run dev
```

브라우저에서 http://127.0.0.1:5173 을 엽니다. 로컬 컴퓨터에서만 접속할 수 있습니다.

```sh
npm test
npm run typecheck
npm run build
npm run preview
```

빌드 결과는 `dist/`입니다. 모델과 폰트도 포함되며 상대 경로를 사용합니다. 이번 단계에서는 외부 서버 배포를 진행하지 않습니다.

## 3단계 화면 확인하기

기본 주소는 개발용 상태 선택 목록입니다. 아래 주소는 앱에 들어갈 UI만 표시합니다.

| 화면                          | 주소                                              |
| ----------------------------- | ------------------------------------------------- |
| 첫 입장: 온보딩 → 숲          | `?view=forest&scenario=first`                     |
| 4/5일 성장 카드·바텀 시트     | `?view=forest&scenario=growing`                   |
| 수종별 완성 안내              | `?view=forest&scenario=pine` / `oak` / `big_tree` |
| 미확인 나무 3그루 순차 안내   | `?view=forest&scenario=backlog`                   |
| 마지막 씨앗·79일              | `?view=forest&scenario=last-seed`                 |
| 마지막 나무 확인·숲 완성      | `?view=forest&scenario=full`                      |
| 온보딩 저장 실패 후 재시도    | `?view=forest&scenario=start-error`               |
| 나무 확인 저장 실패 후 재시도 | `?view=forest&scenario=tree-error`                |
| 기존 2단계 3D 미리보기        | `?view=preview`                                   |

위 미리보기 주소는 메모리 기반 데모 어댑터를 사용합니다. 새로고침하면 초기 상태로 돌아가며 뒤로가기는 개발용 목록으로 돌아갑니다. 앱 전용 주소에서는 네이티브 홈으로 이동합니다. 상태 선택 목록·나무 수/종류 선택은 실제 앱 화면에 포함하지 않습니다.

성장 카드를 누르면 아래에서 시트가 올라옵니다. 닫기 손잡이, 손잡이 아래로 드래그, 바깥 영역 클릭, Escape로 닫을 수 있습니다. 모달의 키보드 포커스는 내부에 머물고 닫으면 원래 요소로 복귀합니다.

온보딩은 미완료일 때 시작 소개(시작하기) → 씨앗 성장 안내(확인) 순서로 두 장을 표시하며 마지막 확인 저장 성공 후에만 숲으로 이동합니다. 나무 완성은 미확인 획득 회차순으로 표시합니다. 종류와 위치는 전달된 스냅샷을 그대로 사용하며 웹에서 추첨하거나 나무를 추가하지 않습니다. 미확인 나무는 연출 전까지 화면에서만 숨기고, 심기 연출 후 확인 저장에 성공하면 다음 안내로 넘어갑니다. 실패 시 같은 나무를 재시도하며 중복 클릭을 막습니다. 16그루 완료 시 다음 씨앗과 성장 시트를 표시하지 않습니다.

## 2단계 3D 모델 확인하기

- 빈 땅 / 1그루 / 8그루 / 16그루를 전환합니다.
- 세 종류를 함께 표시하거나 소나무·참나무·빅트리를 각각 표시합니다.
- 드래그로 회전하고 휠 또는 두 손가락으로 확대합니다. 화면의 확대·축소 버튼도 사용할 수 있습니다.
- 캔버스에 키보드 포커스를 두면 방향키로 회전, `+`/`-`로 확대·축소, `Home`으로 시점을 초기화합니다.
- 배치 칸 표시를 켜 4×4 위치를 확인합니다. 나무 수를 바꾸어도 기존 샘플의 위치는 유지됩니다.
- 로딩 실패나 WebGL 연결 중단 시 다시 불러오기 버튼을 제공합니다. WebGL을 지원하는 브라우저가 필요합니다.

## 원본 모델과 배치

사용자가 제작한 GLB를 변경 없이 복사했습니다. 선리프는 사용하지 않습니다.

| 원본 파일                              | 웹 에셋                    |
| -------------------------------------- | -------------------------- |
| grass_ground_4x4/garden-ground-4x4.glb | public/models/ground.glb   |
| pine_tree/garden-pine.glb              | public/models/pine.glb     |
| oak_tree/garden-oak.glb                | public/models/oak.glb      |
| big_tree/big_tree.glb                  | public/models/big-tree.glb |

땅의 가로·세로를 4단위로 정규화하고 윗면을 Y=0에 맞춥니다. 나무는 균일 스케일로 원본 비율을 유지하며 밑면을 땅에 맞춥니다. 수종별 높이·폭 제한은 `src/forest/assets.ts`에서 조정합니다.

원본 땅의 행 0은 +Z, 열 0은 -X입니다. Room의 `slotIndex`를 `row = slotIndex / 4`, `column = slotIndex % 4`로 해석하여 각 칸 중앙에 배치합니다. 실제 무작위 선정은 앱의 책임이며 웹은 전달받은 종류와 위치를 표시합니다.

모델 템플릿의 geometry와 material을 복제 나무들이 공유합니다. 정지 상태에서는 연속 렌더링을 하지 않고 화면 밖·백그라운드에서는 렌더링을 멈춥니다. 화면 해제 시 요청·이벤트·GPU 자원을 정리합니다. 현재 GLB에는 외부 텍스처와 애니메이션이 없습니다.

## 코드 구성과 다음 단계

- `src/forest`: 모델 로딩, 배치 검증, 카메라 및 3D 캔버스
- `src/flow`: 앱용 화면·컴포넌트와 UI 상태 전환. `ForestCommands`로 저장·뒤로가기 동작을 주입
- `src/preview`: 실제 앱과 분리한 샘플, 메모리 데모 어댑터, 검토용 컨트롤
- `src/bridge`: 버전 1 메시지 및 Android/iOS 브릿지. 요청·응답 연결, 시간 초과, 스냅샷 revision 검증과 갱신 처리
- `tests`: 칸 배치, 샘플 일관성, 실제 GLB 정규화, 로딩 실패·취소, 공유 자원 해제 검증

4단계에서 홈 진입과 WebView 브릿지, Room 스냅샷 관찰 및 명령 응답을 연결했습니다. 온보딩 및 나무 확인 상태의 영속 저장은 앱 Room이 담당합니다. 빌드 URL 주입과 Android/iOS 실행 방법은 [네이티브 연결 문서](../client/docs/design/forest-web-bridge.md)를 참고하세요. 브라우저에서 `?view=app`을 단독으로 열면 앱 진입 안내가 표시됩니다.

## 3단계 시안과 에셋

Figma 파일 `AoRETtkXoDQFXgF544UFIo`의 아래 노드를 기준으로 구현했습니다.

- 온보딩: `911:11210`, `911:11240`
- 성장 카드·메인: `911:11270`, `911:11513`
- 성장 시트: `911:11454`
- 소나무·참나무·빅트리 완성: `911:11334`, `911:11380`, `911:11417`

`src/assets/forest`의 씨앗·나무 PNG와 뒤로가기·성장 SVG는 Figma 원본을 다운로드한 파일입니다. 런타임에 임시 Figma URL을 사용하지 않습니다. SVG 원본 크기는 뒤로가기 44×44, 성장 아이콘 64×64입니다. 402px 화면에서 씨앗은 안내 338×338, 카드 85×85, 시트 273×273로 표시하며 완성 나무는 소나무 205×324, 참나무 324×324, 빅트리 194×324입니다. 작은 화면에서는 비율을 보존해 축소합니다.

땅과 숲은 앞서 승인된 GLB 렌더링을 재사용합니다. 상태바·시스템 내비게이션은 네이티브 영역으로 남기고 safe-area를 지원합니다. 시트 닫기 손잡이와 숲 전체 완성 카드는 동작·경계 상태를 위한 보완입니다. 앱 화면의 카메라 보조 버튼은 키보드 포커스가 있을 때만 표시합니다.

## 3단계 검증 결과 (2026-11-09)

- Vitest 27개 통과: 기존 15개 + UI 흐름 12개.
- `npm run build` 통과(TypeScript 검사 포함). 기존 Three.js 약 637KB 청크 크기 경고는 유지됩니다.
- 실제 브라우저: 온보딩 2장 → 빈 숲, 0/5·4/5 성장 시트, 닫기/Escape·바깥 영역 클릭, 포커스 복귀 확인.
- 소나무 → 참나무 → 빅트리 순차 안내와 고정 위치 표시, 저장 실패 후 동일 나무 재시도, 온보딩 저장 재시도, 16그루 완료 상태 확인.
- 402×844 및 320×568 브라우저 화면에서 가로 넘침 없이 카드·시트 표시 확인. 3단계 당시에는 실제 단말 터치 및 네이티브 WebView를 검증하지 않았습니다.

## 4단계 검증 결과 (2026-11-09)

- Vitest 34개 통과: 기존 27개 + 네이티브 브릿지 7개.
- TypeScript 검사·프로덕션 빌드 통과. 기존 Three.js 청크 크기 경고는 유지됩니다.
- Android WebView에서 홈 진입 → 온보딩 저장 → 실제 Room 성장 상태 → 성장 시트 → 시스템 뒤로가기 → 홈 복귀 → 재진입 시 온보딩 생략 확인.
- Android WebView의 `100dvh` 높이 0 문제를 호스트 높이 기반 CSS 변수로 수정했습니다.
- Android/iOS의 실제 Room 브릿지 저장·DB 재오픈 통합 테스트 통과. iOS 수동 WKWebView 흐름은 아직 미검증입니다.
