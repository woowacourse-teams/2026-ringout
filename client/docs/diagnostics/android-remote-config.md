# Android Remote Config

`android_min_version_code`는 최소 지원 Android `versionCode`를 나타내는 양의 정수다. 앱에 포함된 기본값은 `1`이며, 실제 최소 지원 기준은 Play 배포 이력과 지원 정책을 확인한 뒤 정한다. 현재 앱의 `BuildConfig.VERSION_CODE`가 이 값보다 작으면 강제 업데이트 안내를 표시한다. 같은 버전과 그 이상은 허용한다.

앱은 시작할 때 이전에 활성화된 값이나 앱 기본값을 표시하고, 백그라운드에서 설정을 가져와 활성화한다. 일반 fetch는 Firebase의 기본 최소 간격을 사용한다. 포그라운드의 실시간 리스너는 변경된 설정을 자동으로 가져오며 앱이 활성화한 뒤 새 값을 표시한다. 개발자 도구의 수동 새로고침은 로컬 최소 fetch 간격을 우회하지만 Firebase 요청 제한은 적용된다.

첫 실행에 오프라인이면 앱 기본값을 사용한다. 이전에 활성화한 원격값이 있으면 fetch에 실패해도 그 값을 사용한다. 원격값이 양의 정수가 아니거나 `Int` 범위를 벗어나면 앱 기본값을 사용하고 개발자 도구에 유효하지 않은 원격값임을 표시한다. 마지막 가져오기 성공 시각은 Firebase의 성공한 fetch 시각이며 설정이 활성화된 시각과 다를 수 있다.

## 콘솔 설정

- 앱이 연결되는 Firebase 프로젝트를 확인하고 클라이언트 Remote Config의 `android_min_version_code`를 Number로 설정한다. 지원 기준을 정하기 전 콘솔 기본값은 `1`을 사용한다.
- 변경사항은 저장한 뒤 게시해야 한다. 실시간 동작을 위해 해당 프로젝트의 Firebase Remote Config Realtime API 활성화 여부를 확인한다.
- 변경값 실험은 테스트 프로젝트 또는 테스트 기기만 대상으로 하는 조건을 사용한다. Remote Config에는 비밀 값을 넣지 않는다.

## 기기 검증

테스트용 Firebase 프로젝트와 앱이 연결된 기기에서 확인한다. 새로 설치하거나 앱 데이터를 삭제하면 기존 데이터가 지워질 수 있으므로 별도의 테스트 설치를 사용한다.

1. 첫 실행을 오프라인에서 시작해 개발자 도구에 기본값 `1`과 앱 기본값 출처가 표시되는지 확인한다.
2. 온라인으로 전환해 설정을 가져온 뒤 오프라인으로 다시 실행하고 마지막 활성화 값이 유지되는지 확인한다.
3. 앱을 포그라운드로 열어 둔 상태에서 테스트 대상에만 적용되는 값을 게시한다. 게시 시각과 개발자 도구에 바뀐 값이 표시된 시각을 기록하고 차이를 계산한다.
4. 수동 새로고침과 네트워크 실패 상태를 확인하고, 앱 화면 캡처 또는 영상을 남긴다.

실시간 반영 시간은 네트워크 상태와 기기의 실행 상태에 따라 달라지므로 모든 기기에 즉시 적용된다고 보장할 수 없다. 기기 실측 및 캡처는 아직 수행하지 않았다.

## 강제 업데이트 동작

- 시작 시 Firebase에 저장된 활성화 값과 인앱 기본값을 읽는 동안 일반 앱 화면을 열지 않는다. 서버 fetch 완료는 기다리지 않는다.
- 첫 실행 오프라인, 잘못된 원격값, 로컬 초기화 실패는 기본값 `1`로 진행한다. 이전에 활성화한 유효한 값은 오프라인에서도 차단 기준으로 유지한다.
- 최소 버전 미달이면 피그마의 `업데이트 공지` 다이얼로그를 표시한다. 취소 버튼이 없으며 뒤로가기·바깥 터치로 닫을 수 없다. 일반 화면과 알림 목적지로 이동하지 않는다.
- `스토어로 이동`은 Play 스토어를 열고, 실행할 수 없으면 웹 상세 페이지를 연다. 둘 다 실패하면 오류를 표시하고 다시 누를 수 있다. 스토어를 열거나 업데이트 없이 돌아오는 것만으로 차단이 해제되지 않는다.
- 실시간으로 지원 기준을 낮춰 현재 버전이 기준을 충족하면 차단을 해제한다. 기준을 충족한 새 앱으로 업데이트하여 다시 시작해도 해제된다.
- 울리는 알람, 목적지 추적, 재울림 준비 중에는 해당 알람·미션을 완료할 수 있다. 이 동안 일반 앱 화면은 열지 않는다. 미션 강제 종료의 완료 확인·실패 재시도까지 유지하고 이후 차단한다. 알람 서비스와 예약은 중단하지 않는다.
- 차단 중 받은 모임 알림 요청은 저장하며 일반 앱 진입이 허용된 뒤 기존 인증·내비게이션 규칙에 따라 처리한다. 기존 권장 업데이트 다이얼로그는 강제 차단 중 표시하지 않는다.

## 강제 업데이트 수동 검증

테스트 전 현재 설치 버전 코드 `N`을 개발자 도구에서 기록한다. 아래 값은 테스트 프로젝트 또는 테스트 기기 조건에만 게시한다. 운영 기준을 올릴 때는 대상 사용자가 실제로 설치할 수 있는 Play 버전이 먼저 배포되어 있어야 한다.

| 시나리오 | 조작 | 기대 결과 |
| --- | --- | --- |
| 경계값 | 최소값을 `N-1`, `N`, `N+1`로 변경 | `N+1`에서만 차단 |
| 실시간 반영 | 앱 실행 중 `N+1` 게시 | 재시작 없이 다이얼로그 표시, 일반 화면 접근 불가 |
| 닫힘 방지 | 뒤로가기, 바깥 터치, 홈 이동 후 복귀 | 차단 유지 |
| 스토어 복귀 | 스토어에서 설치하지 않고 복귀 | 차단 유지 |
| 오프라인 캐시 | `N+1` 활성화 후 오프라인 재시작 | 캐시 초기화 후 차단, 일반 화면이 먼저 표시되지 않음 |
| 첫 실행 오프라인 | 데이터 없는 별도 테스트 설치에서 오프라인 실행 | 기본값 `1`로 진입 |
| 잘못된 값 | `0`, 음수, 소수 등 테스트값 게시 | 기본값 `1` 적용 |
| 기준 복구 | 차단된 앱에 `N` 게시 | 차단 해제, 대기 중인 알림 처리 |
| 알람 | 알람 울림·추적·재울림 준비 각각에서 `N+1` 게시 | 알람·미션 완료 흐름 유지, 일반 화면 이동 불가, 종료 후 차단 |
| 종료 확인 | 강제 종료 처리 중 화면 재생성 | 요청 중복 없이 처리·확인 유지, 확인 후 차단 |
| 알림 | 차단 중 모임 알림 클릭, 알람 화면에서 앱으로 복귀 | 알림 요청 보존, 차단 해제 후 기존 규칙으로 이동 |
| 스토어 없음 | Play 스토어 없는 기기 | 웹 상세 페이지 이동, 브라우저도 없으면 오류·재시도 제공 |
| 설치 업데이트 | 설치 가능한 새 버전으로 업데이트 후 재실행 | 새 버전 코드가 최소값 이상이면 진입 |

콘솔 게시부터 실제 화면 반영까지의 시간과 화면 녹화는 실제 Firebase 연결 기기에서 별도로 기록한다. Robolectric 렌더와 자동 테스트는 이 실측을 대체하지 않는다.
