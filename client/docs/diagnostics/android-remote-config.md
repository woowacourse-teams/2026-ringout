# Android Remote Config

`android_min_version_code`는 최소 지원 Android `versionCode`를 나타내는 양의 정수다. 앱에 포함된 기본값은 `1`이며, 실제 최소 지원 기준은 Play 배포 이력과 지원 정책을 확인한 뒤 정한다. 이 설정을 받는 것만으로 업데이트를 강제하지 않는다.

앱은 시작할 때 이전에 활성화된 값이나 앱 기본값을 표시하고, 백그라운드에서 설정을 가져와 활성화한다. 일반 fetch는 Firebase의 기본 최소 간격을 사용한다. 포그라운드의 실시간 리스너는 변경된 설정을 자동으로 가져오며 앱이 활성화한 뒤 새 값을 표시한다. 개발자 도구의 수동 새로고침은 로컬 최소 fetch 간격을 우회하지만 Firebase 요청 제한은 적용된다.

첫 실행에 오프라인이면 앱 기본값을 사용한다. 이전에 활성화한 원격값이 있으면 fetch에 실패해도 그 값을 사용한다. 원격값이 양의 정수가 아니거나 `Int` 범위를 벗어나면 앱 기본값을 사용하고 개발자 도구에 유효하지 않은 원격값임을 표시한다. 마지막 가져오기 성공 시각은 Firebase의 성공한 fetch 시각이며 설정이 활성화된 시각과 다를 수 있다.

## 콘솔 설정

- 앱이 연결되는 Firebase 프로젝트를 확인하고 클라이언트 Remote Config의 `android_min_version_code`를 Number로 설정한다. 지원 기준을 정하기 전 콘솔 기본값은 `1`을 사용한다.
- 변경사항은 저장한 뒤 게시해야 한다. 실시간 동작을 위해 해당 프로젝트의 Firebase Remote Config Realtime API 활성화 여부를 확인한다.
- 변경값 실험은 테스트 프로젝트 또는 테스트 기기만 대상으로 하는 조건을 사용한다. Remote Config에는 비밀 값을 넣지 않는다.

## 기기 검증

테스트용 Firebase 프로젝트와 앱이 연결된 기기에서 확인한다. 새로 설치하거나 앱 데이터를 삭제하면 기존 데이터가 지워질 수 있으므로 별도의 테스트 설치를 사용한다.

1. 첫 실행을 오프라인에서 시작해 개발자 도구에 기본값 `1`과 앱 기본값 출처가 표시되는지 확인한다.
2. 온라인으로 전환해 설정을 가져온 뒤 오프라인으로 다시 실행하고 마지막 활성화 값이 유지되는지 확인한다.
3. 앱을 포그라운드로 열어 둔 상태에서 테스트 대상에만 적용되는 값을 게시한다. 게시 시각과 개발자 도구에 바뀐 값이 표시된 시각을 기록하고 차이를 계산한다.
4. 수동 새로고침과 네트워크 실패 상태를 확인하고, 앱 화면 캡처 또는 영상을 남긴다.

실시간 반영 시간은 네트워크 상태와 기기의 실행 상태에 따라 달라지므로 모든 기기에 즉시 적용된다고 보장할 수 없다. 기기 실측 및 캡처는 아직 수행하지 않았다.
