# 숲 키우기 — 1단계 성장·저장

관련 이슈: [#651](https://github.com/woowacourse-teams/2026-ringout/issues/651)

## 저장 책임

앱 로컬 Room DB가 숲의 원본이다. 웹 화면 없이도 미션 성공을 저장할 때 나무를 심는다.
`ForestRepository`는 숲 상태 조회·관찰, 온보딩 완료, 나무 완성 안내 확인을 제공한다.
웹이나 UI에서 나무 종류·위치·성장 횟수를 설정하는 API는 제공하지 않는다.
Android와 iOS의 AppContainer에 같은 RoomForestRepository를 연결한다.

## 성장 규칙

- 기존 `arrival_results`에 포함된 서로 다른 성공 날짜를 센다. 연속 출석은 필요하지 않다.
- 같은 날 여러 번 도착해도 하루만 성장한다. 실패, 완료 시각 없는 기록, 기존 성장 활성화 이전 미션은 포함하지 않는다.
- 5일마다 나무 한 그루를 즉시 심는다. 심은 직후 다음 씨앗은 0/5가 되며, 다음 성공 날짜에 1/5가 된다.
- 숲은 4×4, 최대 16그루다. 80일에 완성하며 이후 도착은 기록하되 숲 성장은 늘지 않는다.
- `ForestGrowth.successfulDayCount`는 원래 누적 도착 일수이고 `growthDayCount`만 80으로 제한한다.
- 숲 완성 시 `hasGrowingSeed=false`, `remainingDays=0`이다. UI는 이때 다음 씨앗을 표시하지 않는다.
- 기존 ArrivalGrowth와 도착·공유 화면은 이번 단계에서 변경하지 않는다. 도착 화면은 다섯째 날 완성 나무를 보여주는 기존 규칙을 계속 사용한다.

| 성공 날짜 수 | 심은 나무 | 현재 씨앗 | 다음 나무까지 |
| --- | --- | --- | --- |
| 0 | 0 | 0/5 | 5일 |
| 4 | 0 | 4/5 | 1일 |
| 5 | 1 | 0/5 | 5일 |
| 6 | 1 | 1/5 | 4일 |
| 79 | 15 | 4/5 | 1일 |
| 80 이상 | 16 | 없음 | 숲 완성 |

## 나무 종류와 위치

완성할 때 `pine`(소나무), `oak`(참나무), `big_tree`(빅트리)를 동일 확률로 선택한다.
빈 칸 중 하나를 동일 확률로 선택해 결과를 저장한다. 다시 조회하거나 앱을 재시작해도 추첨하지 않는다.

- `growthCycle`: 1~16의 고유 획득 회차. 1회차는 5일, 2회차는 10일에 획득한다.
- `slotIndex`: 0~15의 고유 칸 번호. 행은 `slotIndex / 4`, 열은 `slotIndex % 4`이며 실제 3D 좌표는 2단계에서 매핑한다.
- `plantedAtEpochMillis`: 해당 성장 회차를 완성한 도착 결과의 완료 시각.
- `acknowledgedAtEpochMillis`: 완성 안내를 확인한 시각. null이어도 나무는 이미 심어진 상태다.

에셋은 땅 `garden-ground-4x4.glb`, 소나무 `garden-pine.glb`, 참나무 `garden-oak.glb`, 빅트리 `big_tree.glb`를 사용한다.
빅트리는 사용자가 지정한 `/Users/joon/Documents/06_MODEL/01_RINGOUT/big_tree/big_tree.glb`다.
이번 단계는 에셋 복사나 3D 화면 구현을 포함하지 않는다.

## 스키마와 트랜잭션

Room 14→15에서 `forest_trees`와 단일 행 `forest_state`를 추가한다.

- `forest_trees`는 성장 회차를 기본 키로, 칸 번호를 고유 인덱스로 사용한다.
- `forest_state`는 숲 온보딩 완료 시각을 저장한다. 신규 설치·업데이트 모두 미완료로 시작한다.
- 업데이트 시 기존 도착 결과 중 실제 성장한 5·10·…·80일의 결과로 나무를 채운다. 이전 버전에서 제외했던 과거 미션 이력을 새로 포함하지 않는다.
- 마이그레이션에서 나무를 저장하므로 숲 화면을 처음 열기 전에도 획득 내역이 준비된다.
- 새 도착은 미션·시각·도착 결과·나무를 같은 트랜잭션에서 저장한다. 나무 저장 실패도 전체를 롤백하고 기존 미션 저장 재시도 경로로 복구한다.
- 관찰 쿼리는 성장 일수·나무 목록·온보딩 상태를 하나의 SQL 스냅샷으로 반환한다. 새 성장 횟수와 이전 나무 목록을 섞어 전달하지 않는다.

## 다음 단계 연결 규약

- `getForest()` / `observeForest()`로 상태를 읽는다.
- `completeOnboarding(time)`은 첫 완료 시각만 저장한다.
- `acknowledgeTree(growthCycle, time)`은 지정한 나무의 첫 확인 시각만 저장한다. 다른 나무나 도착 화면의 확인 상태에는 영향을 주지 않는다.
- 존재하지 않는 미래 회차를 확인해도 나무를 만들거나 미리 확인 처리하지 않는다.
- `pendingTrees`는 미확인 나무를 성장 회차순으로 반환한다. UI가 온보딩 이후 순서대로 안내한다.
- ‘나무 심기!’ 연출을 끝내고 확인을 저장한다. 중간 종료 시 나무 자체는 유지되고 안내만 다시 표시할 수 있다.
- 저장 오류는 호출자에게 전달한다. UI는 성공 응답을 받은 후 완료 상태로 전환하고, 실패 시 재시도를 제공한다.
- 온보딩·안내 확인은 로컬 DB에 저장하며 이번 범위에 계정별 서버 동기화는 없다.

## 검증

공통 도메인 테스트와 Android SQLite·iOS Bundled SQLite에서 동일하게 실행하는 DB 계약 테스트를 추가했다.
성장 경계, 종류 선택·빈 칸 배치, 중복·동시 도착, 재시작, 마이그레이션, 트랜잭션 롤백,
온보딩·완성 안내 확인의 독립성, 관찰 상태의 일관성을 검증한다.

```sh
./gradlew :shared:testAndroidHostTest :shared:iosSimulatorArm64Test \
  :androidApp:lintRelease -PciVerification=true --no-configuration-cache
```

WebView·홈 버튼·3D 표시 검증은 각각 해당 단계에서 진행한다.

2026-11-09 검증 결과:

- Android 호스트 테스트 1,434개, iOS 시뮬레이터 테스트 1,372개 통과. 실패·오류·건너뜀 0개.
- 새 숲 테스트는 플랫폼별 17개(도메인 6개, DB 계약 11개).
- Android `lintRelease` 통과.
- 스키마 14와 15를 비교해 기존 테이블 변경 없이 숲 테이블 2개만 추가된 것을 확인했다.
