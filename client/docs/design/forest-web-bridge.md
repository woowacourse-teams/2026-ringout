# 숲 WebView와 네이티브 데이터 연결

홈 우측 상단의 기존 씨앗 애니메이션 버튼으로 숲 화면에 진입한다. Android는 WebView, iOS는 WKWebView를 사용한다. [#705](https://github.com/woowacourse-teams/2026-ringout/issues/705)부터 성장·나무 종류·배치는 인증된 `GET /api/v1/forest` 응답을 사용한다. 웹에 인증 토큰을 전달하지 않으며, 서버 DTO는 앱에서 Domain 상태로 변환한다. 기존 로컬 Room 숲과 서버 숲은 병합하지 않는다.

## URL 설정

개발 기본 주소는 `client/gradle.properties`의 `ringoutForestWebUrl=https://d17x5o0rdpjf2e.cloudfront.net/`이다. Android와 iOS 모두 빌드 시 주소를 반영한다.

우선순위는 **비어 있지 않은 환경 변수 `RINGOUT_FOREST_WEB_URL` → Gradle 속성 `ringoutForestWebUrl` → 빈 문자열**이다. 환경 변수의 앞뒤 공백은 제거하며, 빈 값이나 공백뿐인 값은 미설정으로 취급한다. 환경 변수가 설정돼 있으면 명령행 `-PringoutForestWebUrl=...`보다도 우선한다. 속성과 환경 변수를 모두 제거하면 앱에 안내와 홈 이동 버튼을 표시한다.

CD는 GitHub Environment의 Variables에 등록한 `RINGOUT_FOREST_WEB_URL`을 빌드 잡에 주입한다. Android는 `build-release-aab.yml`의 `internal`/`production`, iOS는 `ios-internal-cd.yml`의 `ios-internal`과 `ios-production-cd.yml`의 `ios-production`을 사용한다. 내부 배포에서는 변수 미등록 시 개발 기본 주소를 사용한다. 운영 배포에서는 HTTPS 주소가 없으면 빌드 전에 실패한다. 운영 주소는 `production`과 `ios-production`에 각각 등록해야 한다. Android의 업로드 전용 CD 잡에서 설정을 바꿔도 이미 생성된 AAB에는 반영되지 않는다.

주소에 쿼리·fragment·인증 정보를 넣지 않는다. 앱이 `?view=app`을 붙인다. 배포 시에는 리다이렉트가 없는 최종 HTTPS 문서 주소를 사용한다. HTTP는 디버그 빌드의 loopback 주소에만 허용한다.

### Android 로컬 실행

저장소의 `web` 디렉터리에서:

```sh
npm ci
npm run dev
```

`client` 디렉터리에서 연결된 에뮬레이터/기기에 실행한다. 여러 기기가 연결되어 있다면 adb에 `-s <serial>`을 추가한다.

```sh
adb reverse tcp:5173 tcp:5173
RINGOUT_FOREST_WEB_URL=http://127.0.0.1:5173/ ./gradlew :androidApp:installDebug
```

앱을 열고 홈 우측 상단 씨앗을 누른다. Android Studio 실행에서도 로컬 주소를 사용하려면 Gradle 빌드 프로세스에 같은 환경 변수를 전달한다. 환경 변수가 없을 때는 Gradle 실행 인자의 `-PringoutForestWebUrl=http://127.0.0.1:5173/`로도 지정할 수 있다. 별도 설정 없이 빌드하면 개발 기본 주소를 사용한다.

### iOS 시뮬레이터 빌드

기본 설정으로 Xcode에서 빌드하면 개발 기본 주소를 사용한다. 로컬 웹 서버로 검증할 때는 웹 서버를 실행하고 `client`에서 아래 명령을 실행한다. `gradle.properties`를 변경할 필요는 없다.

```sh
RINGOUT_FOREST_WEB_URL=http://127.0.0.1:5173/ xcodebuild \
  -project iosApp/iosApp.xcodeproj -scheme iosApp -configuration Debug \
  -sdk iphonesimulator -destination 'generic/platform=iOS Simulator' \
  -derivedDataPath /private/tmp/ringout-forest-stage4-xcode CODE_SIGNING_ALLOWED=NO build
```

환경 변수는 Kotlin 프레임워크를 빌드하는 프로세스에 전달해야 한다. iOS 실기기의 loopback은 Mac 개발 서버를 가리키지 않으므로 실기기에서는 HTTPS 개발 주소가 필요하다.

## 데이터 흐름

- 숲 화면 진입 시 API 조회와 웹 로딩을 함께 시작한다. API 조회 성공과 웹 `forest.ready`가 모두 준비되면 버전 1 스냅샷을 전달하고 초기 로딩을 종료한다.
- 화면 재진입·숲 화면으로 앱 복귀·조회 실패 후 재시도 시 다시 조회한다. 로그인 자체나 웹 내부 화면 이동은 조회를 발생시키지 않는다.
- 현재 계정의 outbox에서 `ARRIVED`가 `SENT`로 바뀌면 숲이 보이는 동안 추가 조회한다. 최초 관찰 값은 진입 조회와 합친다. 조회 도중 전송이 성공하면 진행 중 요청이 끝난 후 한 번 더 조회한다.
- `refreshForest()`만 서버를 조회한다. `getForest()`와 `observeForest()`는 현재 세션의 스냅샷을 읽고 관찰한다. WebView 재로딩은 최신 스냅샷으로 새 연결을 준비하며 API를 중복 호출하지 않는다.
- 웹은 준비 요청을 10초 후 만료시킨다. 앱이 8초 안에 초기 스냅샷을 전달할 수 없으면 조회 성공·포그라운드 복귀 이후 페이지를 새로 준비한다. 이미 받은 API 결과를 재사용하므로 느린 조회나 늦은 재시도 때문에 웹 오류 화면에 머물지 않는다.
- 서버가 반환한 성장 상태와 나무 목록을 표시한다. 성공 일수에 비해 나무 목록이 적은 상태는 정상이며, 클라이언트가 빠진 나무를 생성하지 않는다.
- 이미 표시한 숲을 갱신할 때는 기존 화면을 유지한다. 초기 조회 실패는 오류와 재시도·홈 이동을 표시하고, 갱신 실패는 기존 숲에 재시도 안내를 표시한다. 실패를 빈 숲으로 바꾸지 않는다.
- 요청 ID로 응답을 연결하고 중복 저장을 방지한다. 스냅샷 revision과 연결·인증 세션의 수명으로 이전 응답이 최신 화면을 되돌리지 않도록 한다.
- 페이지 재시작 시 이전 페이지의 비동기 응답을 취소한다. 화면 종료 후에는 응답을 전달하지 않는다. 백그라운드에서는 새 갱신 요청과 웹 상태 전달을 중지하고 복귀 시 다시 조회한다.
- 시스템 뒤로가기는 웹에 전달하여 열린 시트를 먼저 닫는다. 일반 숲 화면에서는 웹의 뒤로가기 요청을 받아 앱 홈으로 돌아간다.

### 온보딩 완료와 서버 동기화 (#707)

신규 사용자는 숲 조회 GET 이후 온보딩을 본다. 첫 화면의 `시작하기`는 안내 페이지를 넘기며, 두 번째 안내의 `확인`이 `forest.completeOnboarding`을 보낸다. 앱은 최초 확인 시각을 계정별 DataStore에 영구 저장한 다음 즉시 최신 스냅샷으로 응답한다. 웹은 서버 요청을 기다리지 않고 숲으로 이동한다. 로컬 저장 자체가 실패하면 기존 안내 화면의 오류·재시도를 사용한다.

앱 공통 동기화 작업이 `PUT /api/v1/forest/onboarding`에 저장된 시각을 `completedAt`으로 전송한다. 요청은 ISO-8601 UTC `Z` 형식을 사용하며, 재클릭·재시도·앱 재시작에도 최초 시각을 유지한다. `200`과 `201` 모두 응답의 `onboardingCompletedAt`을 최종 시각으로 저장하고 동기화 완료로 표시한다. 서버 조회에서 완료 시각을 확인해도 같은 방식으로 확정한다. 늦게 도착한 GET의 null은 이미 확정된 완료 시각을 지우지 않으며, PUT 응답은 최신 성장·나무 목록을 되돌리지 않는다.

- 기존 계정별 로컬 완료 기록은 미전송으로 읽어 자동 이관한다. 나무 확인 기록은 유지한다. 계정 정보가 없는 과거 Room 온보딩 기록은 가져오지 않는다.
- 로컬 기록 변경·로그인·앱 복귀·네트워크 복구와 저장된 재시도 기한에 현재 계정의 미전송 기록을 처리한다. 기존 미전송 기록이 있으면 PUT이 숲 GET보다 먼저 또는 동시에 실행될 수 있다. 숲 조회가 PUT 완료를 기다리지는 않는다.
- 네트워크 오류·시간 초과·`408/429/5xx`는 5초부터 지수 증가해 최대 15분 간격으로 재시도한다. 자동 재시도는 저장된 대기시간을 준수하며 수동 재시도는 즉시 전송 기회를 만든다.
- `401`은 공통 토큰 재발급 흐름으로 처리하며, 재인증이 필요하면 기록을 보존하고 전송을 보류한다. `400` 또는 잘못된 성공 응답은 자동 재시도를 중단한다.
- 자동 재시도를 중단한 상태는 숲 화면의 별도 비차단 안내와 재시도로 표시한다. GET 갱신 성공이 이 안내를 지우지 않으며, 전송 실패로 숲 사용이나 로컬 온보딩 완료를 되돌리지 않는다.
- 화면을 나가도 동기화는 앱 프로세스에서 계속된다. OS가 실행을 중단하거나 앱을 종료한 경우 다음 실행·로그인에서 기록을 복구한다. 별도 WorkManager/BGTask 실행 보장은 이번 범위에 없다.
- 계정별 요청을 직렬화하고 로그인 변경 전후를 검증한다. 이전 계정의 늦은 응답은 현재 계정의 숲에 반영하지 않는다.

서버 전송 전에 앱을 삭제하면 기기에만 저장된 완료 기록은 복원되지 않는다. 서버에 확정된 기록은 재설치·다른 기기에서 GET으로 복원한다.

### 나무 확인의 임시 로컬 저장

`forest.acknowledgeTree`는 아직 계정별 DataStore에 확인 시각을 저장한다. 서버 확인 시각이 있으면 서버 값을 우선하고, null인 경우 같은 계정과 같은 나무(회차·종류·위치·획득 시각)의 로컬 기록을 적용한다. 나무 확인의 서버 저장 API 연결은 후속 범위다.

브릿지는 설정한 origin과 정확한 문서 URL의 최상위 프레임만 허용한다. 외부 페이지 이동과 임의 파일 접근은 허용하지 않는다. 웹 단독 `?view=app` 접속은 앱에서 열라는 안내를 표시하며 데모 저장소를 사용하지 않는다. 기존 `?view=forest&scenario=...`는 독립적인 개발용 미리보기다.
