# 숲 WebView와 네이티브 데이터 연결

홈 우측 상단의 기존 씨앗 애니메이션 버튼으로 숲 화면에 진입한다. Android는 WebView, iOS는 WKWebView를 사용한다. [#705](https://github.com/woowacourse-teams/2026-ringout/issues/705)부터 성장·나무 종류·배치는 인증된 `GET /api/v1/forest` 응답을 사용하며, #713부터 나무 저장 PUT으로 확정한 나무도 반영한다. 웹에 인증 토큰을 전달하지 않으며, 서버 DTO는 앱에서 Domain 상태로 변환한다. 기존 로컬 Room 숲과 서버 숲은 병합하지 않는다.

## URL 설정

개발 기본 주소는 `client/gradle.properties`의 `ringoutForestWebUrl=https://d17x5o0rdpjf2e.cloudfront.net/`이다. Android와 iOS 모두 빌드 시 주소를 반영한다.

우선순위는 **비어 있지 않은 환경 변수 `RINGOUT_FOREST_WEB_URL` → Gradle 속성 `ringoutForestWebUrl` → 빈 문자열**이다. 환경 변수의 앞뒤 공백은 제거하며, 빈 값이나 공백뿐인 값은 미설정으로 취급한다. 환경 변수가 설정돼 있으면 명령행 `-PringoutForestWebUrl=...`보다도 우선한다. 속성과 환경 변수를 모두 제거하면 앱에 안내와 홈 이동 버튼을 표시한다.

CD는 GitHub Environment의 Variables에 등록한 `RINGOUT_FOREST_WEB_URL`을 빌드 잡에 주입한다. Android는 `build-release-aab.yml`의 `internal`/`production`, iOS는 `ios-internal-cd.yml`의 `ios-internal`과 `ios-production-cd.yml`의 `ios-production`을 사용한다. 내부 배포에서는 변수 미등록 시 개발 기본 주소를 사용한다. 운영 배포에서는 HTTPS 주소가 없으면 빌드 전에 실패한다. 운영 주소는 `production`과 `ios-production`에 각각 등록해야 한다. Android의 업로드 전용 CD 잡에서 설정을 바꿔도 이미 생성된 AAB에는 반영되지 않는다.

주소에 쿼리·fragment·인증 정보를 넣지 않는다. 앱이 `?view=app`을 붙인다. 배포 시에는 리다이렉트가 없는 최종 HTTPS 문서 주소를 사용한다. HTTP는 디버그 빌드의 loopback 주소에만 허용한다.

### Android 로컬 실행

저장소의 `web` 디렉터리에서:

```sh
npm ci
npm run dev
```

`client` 디렉터리에서 연결된 에뮬레이터/기기에 실행한다. 여러 기기가 연결되어 있다면 adb에 `-s <serial>`을 추가한다.

```sh
adb reverse tcp:5173 tcp:5173
RINGOUT_FOREST_WEB_URL=http://127.0.0.1:5173/ ./gradlew :androidApp:installDebug
```

앱을 열고 홈 우측 상단 씨앗을 누른다. Android Studio 실행에서도 로컬 주소를 사용하려면 Gradle 빌드 프로세스에 같은 환경 변수를 전달한다. 환경 변수가 없을 때는 Gradle 실행 인자의 `-PringoutForestWebUrl=http://127.0.0.1:5173/`로도 지정할 수 있다. 별도 설정 없이 빌드하면 개발 기본 주소를 사용한다.

### iOS 시뮬레이터 빌드

기본 설정으로 Xcode에서 빌드하면 개발 기본 주소를 사용한다. 로컬 웹 서버로 검증할 때는 웹 서버를 실행하고 `client`에서 아래 명령을 실행한다. `gradle.properties`를 변경할 필요는 없다.

```sh
RINGOUT_FOREST_WEB_URL=http://127.0.0.1:5173/ xcodebuild \
  -project iosApp/iosApp.xcodeproj -scheme iosApp -configuration Debug \
  -sdk iphonesimulator -destination 'generic/platform=iOS Simulator' \
  -derivedDataPath /private/tmp/ringout-forest-stage4-xcode CODE_SIGNING_ALLOWED=NO build
```

환경 변수는 Kotlin 프레임워크를 빌드하는 프로세스에 전달해야 한다. iOS 실기기의 loopback은 Mac 개발 서버를 가리키지 않으므로 실기기에서는 HTTPS 개발 주소가 필요하다.

## 데이터 흐름

- 숲 화면 진입 시 API 조회와 웹 로딩을 함께 시작한다. API 조회 성공과 웹 `forest.ready`가 모두 준비되면 버전 1 스냅샷을 전달하고 초기 로딩을 종료한다.
- 화면 재진입·숲 화면으로 앱 복귀·조회 실패 후 재시도 시 다시 조회한다. 로그인 자체나 웹 내부 화면 이동은 조회를 발생시키지 않는다.
- 현재 계정의 outbox에서 `ARRIVED`가 `SENT`로 바뀌면 숲이 보이는 동안 추가 조회한다. 최초 관찰 값은 진입 조회와 합친다. 조회 도중 전송이 성공하면 진행 중 요청이 끝난 후 한 번 더 조회한다.
- 일반 숲 갱신은 `refreshForest()`로 요청한다. `getForest()`와 `observeForest()`는 현재 세션의 스냅샷을 읽고 관찰한다. WebView 재로딩은 최신 스냅샷으로 새 연결을 준비하며 API를 중복 호출하지 않는다. 나무 확인의 404 수동 재시도는 대상 나무 존재 여부를 확인하는 명시적 GET을 별도로 수행한다.
- 웹은 준비 요청을 10초 후 만료시킨다. 앱이 8초 안에 초기 스냅샷을 전달할 수 없으면 조회 성공·포그라운드 복귀 이후 페이지를 새로 준비한다. 이미 받은 API 결과를 재사용하므로 느린 조회나 늦은 재시도 때문에 웹 오류 화면에 머물지 않는다.
- 서버가 반환한 성장 상태와 확정된 나무 목록을 표시한다. 성공 일수에 비해 나무 목록이 적은 상태는 정상이며, 조회 결과의 빈 회차만 보고 나무를 생성하지 않는다. 새 도착 이후 식재 판단은 아래 #713 흐름으로 처리한다.
- 이미 표시한 숲을 갱신할 때는 기존 화면을 유지한다. 초기 조회 실패는 오류와 재시도·홈 이동을 표시하고, 갱신 실패는 기존 숲에 재시도 안내를 표시한다. 실패를 빈 숲으로 바꾸지 않는다.
- 요청 ID로 응답을 연결하고 중복 저장을 방지한다. 스냅샷 revision과 연결·인증 세션의 수명으로 이전 응답이 최신 화면을 되돌리지 않도록 한다.
- 페이지 재시작 시 이전 페이지의 비동기 응답을 취소한다. 화면 종료 후에는 응답을 전달하지 않는다. 백그라운드에서는 화면의 새 갱신 요청과 숲 스냅샷 전달을 중지하고 복귀 시 다시 조회한다. 도착 후 식재 판단과 저장은 화면 수명과 별도로 실행한다. 연출 정지를 위한 가시성 제어 이벤트는 비활성 전환에도 전달한다.
- 시스템 뒤로가기는 웹에 전달하여 열린 시트를 먼저 닫는다. 일반 숲 화면에서는 웹의 뒤로가기 요청을 받아 앱 홈으로 돌아간다.

### 온보딩 완료와 서버 동기화 (#707)

신규 사용자는 숲 조회 GET 이후 온보딩을 본다. 첫 화면의 `시작하기`는 안내 페이지를 넘기며, 두 번째 안내의 `확인`이 `forest.completeOnboarding`을 보낸다. 앱은 최초 확인 시각을 계정별 DataStore에 영구 저장한 다음 즉시 최신 스냅샷으로 응답한다. 웹은 서버 요청을 기다리지 않고 숲으로 이동한다. 로컬 저장 자체가 실패하면 기존 안내 화면의 오류·재시도를 사용한다.

앱 공통 동기화 작업이 `PUT /api/v1/forest/onboarding`에 저장된 시각을 `completedAt`으로 전송한다. 요청은 ISO-8601 UTC `Z` 형식을 사용하며, 재클릭·재시도·앱 재시작에도 최초 시각을 유지한다. `200`과 `201` 모두 응답의 `onboardingCompletedAt`을 최종 시각으로 저장하고 동기화 완료로 표시한다. 서버 조회에서 완료 시각을 확인해도 같은 방식으로 확정한다. 늦게 도착한 GET의 null은 이미 확정된 완료 시각을 지우지 않으며, PUT 응답은 최신 성장·나무 목록을 되돌리지 않는다.

- 기존 계정별 로컬 완료 기록은 미전송으로 읽어 자동 이관한다. 나무 확인 기록은 유지한다. 계정 정보가 없는 과거 Room 온보딩 기록은 가져오지 않는다.
- 로컬 기록 변경·로그인·앱 복귀·네트워크 복구와 저장된 재시도 기한에 현재 계정의 미전송 기록을 처리한다. 기존 미전송 기록이 있으면 PUT이 숲 GET보다 먼저 또는 동시에 실행될 수 있다. 숲 조회가 PUT 완료를 기다리지는 않는다.
- 네트워크 오류·시간 초과·`408/429/5xx`는 5초부터 지수 증가해 최대 15분 간격으로 재시도한다. 자동 재시도는 저장된 대기시간을 준수하며 수동 재시도는 즉시 전송 기회를 만든다.
- `401`은 공통 토큰 재발급 흐름으로 처리하며, 재인증이 필요하면 기록을 보존하고 전송을 보류한다. `400` 또는 잘못된 성공 응답은 자동 재시도를 중단한다.
- 자동 재시도를 중단한 상태는 숲 화면의 별도 비차단 안내와 재시도로 표시한다. GET 갱신 성공이 이 안내를 지우지 않으며, 전송 실패로 숲 사용이나 로컬 온보딩 완료를 되돌리지 않는다.
- 화면을 나가도 동기화는 앱 프로세스에서 계속된다. OS가 실행을 중단하거나 앱을 종료한 경우 다음 실행·로그인에서 기록을 복구한다. 별도 WorkManager/BGTask 실행 보장은 이번 범위에 없다.
- 계정별 요청을 직렬화하고 로그인 변경 전후를 검증한다. 이전 계정의 늦은 응답은 현재 계정의 숲에 반영하지 않는다.

서버 전송 전에 앱을 삭제하면 기기에만 저장된 완료 기록은 복원되지 않는다. 서버에 확정된 기록은 재설치·다른 기기에서 GET으로 복원한다.

### 나무 획득 연출과 확인 동기화 (#709)

GET에 포함된 미확인 나무를 회차순으로 안내한다. 사용자가 `나무 심기!`를 누르면 650ms 크기 연출을 시작하고, 렌더러가 최종 크기의 프레임을 정상적으로 그린 뒤 `forest.acknowledgeTree`를 보낸다. 타이머 경과만으로 확인하지 않는다. 모델과 대상 나무가 준비되기 전에는 시간을 계산하지 않으며, 앱 비활성·문서 숨김·화면 밖에서는 시간을 멈추고 복귀 후 남은 연출을 이어간다. 모션 감소 설정에서는 최종 프레임을 그린 뒤 완료한다. 렌더 실패나 페이지 폐기 시에는 확인하지 않고, 재시도는 새로운 연출 시도로 시작한다.

앱은 버전 1의 `forest.visibility` 이벤트에 현재 준비 요청 ID와 `active` 값을 전달한다. 웹은 자신의 준비 요청 ID와 일치하는 이벤트만 적용한다. 준비 응답보다 먼저 온 상태도 보존하며, 같은 문서에서 새 브릿지로 재시도하면 새 준비 요청 ID를 사용한다. 구버전 웹은 새 이벤트를 무시하고, 구버전 앱을 사용하는 웹은 문서 가시성으로 동작한다.

네이티브는 유효한 확인 명령을 받은 시각을 캡처하고, 계정별 최초 확인 시각과 전송 기록을 하나의 DataStore 갱신으로 저장한 뒤 즉시 웹에 성공을 반환한다. 로컬 저장 실패만 현재 연출 안내에서 재시도하며, 서버 전송 실패로 이미 완료한 연출을 반복하지 않는다.

- `ForestSyncCoordinator`는 온보딩이 서버에서 확정된 뒤 `PATCH /api/v1/forest/trees/{growthCycle}`을 보낸다. 전송 가능한 나무는 회차순으로 처리하되 한 나무의 재시도 대기·차단이 다른 나무를 막지 않는다.
- 요청의 `acknowledgedAt`은 최초 시각의 ISO-8601 UTC `Z` 표현이며 재시작·재시도에도 유지한다. `200`의 나무 식별값과 확인 시각을 검증하고 서버 값을 반영한다. 성장 상태와 다른 나무를 과거 값으로 되돌리지 않는다.
- 나무별 전송 상태·시도 횟수·다음 기한·온보딩 복구 단계를 영구 저장한다. 화면을 닫아도 앱 수명에서 전송하고, 프로세스 종료 시 다음 실행에서 복구한다.
- 네트워크·시간 초과·`408/429/5xx`는 5초부터 최대 15분 간격으로 재시도한다. `401`은 공통 인증 흐름으로 처리한다. `400`·잘못된 성공 응답은 해당 나무를 차단하고 별도 안내와 수동 재시도를 제공한다.
- `404`에서는 나무를 생성하지 않고 보류한다. 오류 이후 시작된 GET에서 같은 나무를 확인하면 저장된 기한을 지켜 재개하며, 이미 확인된 나무이면 완료로 확정한다. 오래된 GET·캐시 읽기·웹 재로딩은 보류 해제 신호가 아니다. 수동 재시도는 GET으로 존재 여부를 확인한 뒤 기한을 건너뛴다.
- 최초 `409`는 저장된 온보딩 시각으로 PUT을 재확정한 뒤 PATCH를 다시 시도한다. 복구 중 네트워크 실패도 기한을 두고 재시도한다. 성공한 복구 뒤 다시 `409`이면 해당 나무의 자동 전송을 중단하고 수동 재시도를 제공한다. 온보딩 완료 UI는 되돌리지 않는다.
- GET의 서버 확인 시각도 전송 완료로 확정한다. 늦은 GET의 null이나 PATCH 실패는 확정한 확인 상태를 지우지 않는다. 이전 계정의 응답과 다른 나무의 확인 기록은 현재 나무에 적용하지 않는다.

기존 `acknowledgedTrees`에만 있는 기록은 **로컬 전용**으로 유지한다. 중복 명령이나 GET null로 전송 기록을 만들지 않으며, 이번 변경 이후 새 확인부터 서버로 동기화한다. 따라서 기존 로컬 확인은 재설치·다른 기기에서 다시 연출될 수 있다. GET의 nonnull 서버 시각으로 기존 값을 보정하는 것은 허용한다.

#709는 서버에 이미 존재하는 나무의 확인을 연결했으며, 나무 저장은 아래 #713에서 연결한다. 실제 연출 완료 기준을 적용하려면 #709의 갱신된 웹 빌드와 앱이 모두 반영되어야 한다.

### 새 도착 이후 나무 저장 (#713)

기존 기기에서 4일 성공한 뒤 재설치한 기기에서 하루 더 도착하면, 서버의 성공일 5일을 기준으로 첫 나무를 저장한다. 로컬에 성공 기록이 한 개뿐이어도 가능하며, 로컬 기록 개수와 서버 성공일 개수의 일치를 요구하지 않는다. 온보딩이나 숲 화면 진입을 기다리지 않는다.

1. ARRIVED 응답의 실행 ID·실제 도착 시각·종료 종류를 확인한다. 계정별 DataStore에 실행 ID와 실제 시각의 획득 판단 대기 기록을 먼저 저장한 뒤, 원본 outbox를 SENT로 표시한다. 두 저장 사이에 종료되면 동일 도착을 재전송하고 판단 기록을 중복 제거한다.
2. 이 도착 성공 이후 시작하는 GET으로 성장 상태를 확인한다. 성공일이 5·10·…·80이고 해당 회차가 서버와 PUT 대기열에 모두 없을 때만 저장 작업을 만든다. 소나무·참나무·빅트리는 각 1/3로 한 번 추첨하고, 실제 도착 시각을 최초 `plantedAt`으로 저장한다. 판단 완료와 PUT 대기는 하나의 DataStore 갱신으로 저장한다.
3. 판단이 영구 저장된 다음 다음 ARRIVED를 전송한다. PUT 응답은 기다리지 않는다. 대기 도착은 실제 시각순이며, 앞선 도착이나 판단이 재시도 중이면 추월하지 않는다. START·해제·강제 종료·모임 이동 전송과 로컬 미션 완료·저널 기록은 계속 처리한다.
4. 공통 숲 동기화 작업이 `PUT /api/v1/forest/trees/{growthCycle}`에 `kind`, ISO-8601 UTC `Z` 형식의 `plantedAt`을 보낸다. 종류와 시각을 다시 만들지 않으며 `slotIndex`는 서버가 배정한다. `200/201` 모두 서버의 종류·칸·획득 시각·확인 시각을 채택한다.
5. 성공한 나무만 스냅샷에 병합하고 기존 획득 연출 및 확인 PATCH로 이어진다. 이미 확인된 나무는 다시 연출하지 않는다. 늦은 GET의 누락이나 늦은 PUT의 null은 확정 나무·확인 상태를 지우지 않으며 최신 성장 상태를 유지한다.

Android의 앱·알람 서비스·Worker와 iOS 도착 복구 경로는 화면과 같은 숲 저장소 및 동기화 런타임을 사용한다. 앱 프로세스가 실행 가능한 동안 전송하고, 남은 작업은 다음 실행·동일 계정 재로그인에서 복구한다. OS가 앱을 종료한 상태에서의 별도 식재 실행 시간을 보장하지 않는다.

- 조회·PUT의 네트워크 오류, 시간 초과, `408/429/5xx`는 5초부터 최대 15분 간격으로 재시도한다. 조회 판단이 실패하면 다음 ARRIVED만 보류하며, PUT 실패는 다음 ARRIVED를 막지 않는다.
- `401`은 공통 인증 처리 후 재인증을 기다린다. `400`·잘못된 응답은 자동 전송을 중단하고 숲에 독립적인 오류 안내와 재시도를 제공한다.
- **식재 PUT의 `409`는 획득 기록 정합성 오류**다. 자동 반복하거나 온보딩 PUT으로 복구하지 않는다. 수동 재시도는 새 GET으로 해당 회차가 저장되었는지만 확인하며, 여전히 없으면 차단 상태를 유지한다. 다른 날짜나 회차를 만들어 보내지 않는다.
- 이미 SENT인 과거 도착을 순회하지 않으며, 기존 로컬 나무나 조회에서 발견한 과거 누락 회차를 소급 이관하지 않는다. 현재 기기 대기열의 순서를 보장하며, 다른 기기의 동시 도착으로 조회 전에 지나간 획득 회차의 완전한 복원은 후속 범위다.

브릿지는 설정한 origin과 정확한 문서 URL의 최상위 프레임만 허용한다. 외부 페이지 이동과 임의 파일 접근은 허용하지 않는다. 웹 단독 `?view=app` 접속은 앱에서 열라는 안내를 표시하며 데모 저장소를 사용하지 않는다. 기존 `?view=forest&scenario=...`는 독립적인 개발용 미리보기다.
