# Ringout 릴리즈 기능 정의서 (초안)

> 문서 상태: Draft  
> 기준 버전: Android `0.0.5`  
> 작성 기준: 2026-07-29 현재 저장소 구현 상태  
> 제안 릴리즈 범위: Android 첫 공개 릴리즈

## 1. 문서 목적

Ringout의 첫 공개 릴리즈에 필요한 기능과 품질 기준을 정의한다.

Ringout은 사용자가 지정한 시각에 알람을 울리고, 알람을 끈 뒤 제한 시간 안에 지정한 목적지에 도착하도록 돕는 알람 앱이다. 첫 릴리즈에서는 **알람이 예정된 시각에 안정적으로 울리고, 목적지 도착 여부를 신뢰할 수 있게 판정하는 것**을 가장 중요한 목표로 둔다.

## 2. 릴리즈 목표

- 사용자가 알람을 생성하고 이후 수정·활성화·비활성화·삭제할 수 있다.
- 앱이 종료되거나 기기가 재부팅되어도 활성 알람이 유지된다.
- 잠금 화면과 절전 상태에서도 알람을 인지할 수 있다.
- 알람 해제 후 목적지 도착 미션의 진행 상태와 결과를 확인할 수 있다.
- 필요한 권한을 사용자가 이해하고 설정할 수 있다.
- 치명적 오류 없이 실제 기기에서 핵심 사용자 흐름을 완료할 수 있다.

## 3. 릴리즈 범위 제안

### 3.1 1차 릴리즈에 포함

- Android 앱
- 알람 생성, 조회, 수정, 활성화/비활성화, 삭제
- 단일 및 요일 반복 알람
- 목적지 지도 검색과 목적지 별칭 설정
- 목적지 도착 제한 시간 설정
- 기기 알람음 선택과 미리 듣기
- 정시 알람, 전체 화면 알람, 진동
- 알람 해제 후 위치 추적 및 도착 판정
- 앱/기기 재시작 후 알람 복구
- 라이트/다크 테마와 앱 버전 표시
- 권한 안내, 오류 처리, 기본 접근성
- 개인정보 처리방침 및 스토어 제출 자료

### 3.2 1차 릴리즈에서 제외 제안

- iOS 공개 배포
- 계정, 로그인, 서버 동기화
- 여러 기기 간 알람 동기화
- 소셜 기능 및 친구와 미션 공유
- 유료 결제, 광고
- 알람 통계 및 습관 분석
- 클라우드 백업

현재 iOS에서는 실제 알람 예약, 지도, 주소 검색이 지원되지 않고 기본 알람음만 제공된다. iOS를 함께 출시하려면 별도의 핵심 기능 구현 및 검증 일정이 필요하다.

## 4. 현재 구현 기준선

코드에서 확인한 현재 상태이며, 릴리즈 완료를 의미하지는 않는다.

| 영역 | 현재 상태 | 릴리즈 전 확인 사항 |
|---|---|---|
| 홈 | 알람 목록, 빈 화면, 다음 알람 안내 | 많은 알람, 긴 텍스트, 시간 변경 검증 |
| 알람 관리 | 생성, 수정, 활성화, 비활성화, 삭제 | 저장 실패와 중복 입력 방어 |
| 반복 | 요일 선택 및 다음 실행 시각 계산 | 일회성 알람 완료 후 상태 검증 |
| 목적지 | Android 지도, 검색, 별칭 입력 | API 오류, 결과 없음, 네트워크 단절 처리 |
| 알람음 | 기기 알람음 목록과 미리 듣기 | 삭제되거나 접근 불가한 URI 대체 처리 |
| 알람 실행 | 정확한 알람, 전체 화면, 포그라운드 서비스 | 제조사별 절전/잠금 화면 실기기 검증 |
| 도착 미션 | 위치 추적, 제한 시간, 도착 거리 판정 | GPS 불량, 권한 회수, 서비스 종료 처리 |
| 복구 | 재부팅, 시간/시간대 변경, 앱 업데이트 시 재예약 | 반복 예약과 중복 실행 방지 검증 |
| 설정 | 테마 선택, 버전 표시 | 권한 상태와 개인정보 메뉴 추가 |
| iOS | 공통 UI 일부만 사용 가능 | 알람·지도·검색의 네이티브 구현 필요 |

## 5. P0 — 출시 필수 기능

P0 항목이 하나라도 완료되지 않으면 공개 릴리즈를 진행하지 않는다.

### 5.1 알람 관리

- [ ] 알람 생성
  - 시각을 선택할 수 있다.
  - 반복 요일을 0개 이상 선택할 수 있다.
  - 목적지와 제한 시간을 설정할 수 있다.
  - 알람음을 선택할 수 있다.
  - 저장 완료 후 홈에서 생성된 알람과 다음 실행 정보를 확인할 수 있다.
- [ ] 알람 수정
  - 기존 값을 불러오고 변경 내용을 저장한다.
  - 수정 전 예약을 취소하고 새 예약을 중복 없이 등록한다.
- [ ] 알람 활성화/비활성화
  - 비활성화하면 예약이 취소된다.
  - 다시 활성화하면 다음 유효 시각으로 예약된다.
- [ ] 알람 삭제
  - 사용자에게 삭제 여부를 확인한다.
  - 저장 데이터와 시스템 예약을 함께 제거한다.
- [ ] 일회성 알람
  - 반복 요일이 없으면 가장 가까운 다음 시각에 한 번 울린다.
  - 실행 완료 후 자동으로 비활성화된다.
- [ ] 반복 알람
  - 선택한 요일에만 울린다.
  - 실행 후 다음 선택 요일로 다시 예약된다.

#### 완료 조건

- 생성, 수정, 토글, 삭제 후 앱을 재시작해도 화면과 시스템 예약 상태가 일치한다.
- 동일 알람이 같은 시각에 두 번 실행되지 않는다.
- 과거 시각, 자정, 월말, 연말, 윤년, 시간대 변경 조건에서 다음 실행 시각이 올바르다.

### 5.2 알람 울림

- [ ] 예약 시각에 소리와 진동을 시작한다.
- [ ] 화면이 꺼져 있거나 잠겨 있어도 알람 화면을 표시한다.
- [ ] 앱이 백그라운드에 있거나 종료되어 있어도 동작한다.
- [ ] 사용자가 선택한 알람음을 재생한다.
- [ ] 선택한 알람음을 사용할 수 없으면 기본 알람음으로 대체한다.
- [ ] 알람 화면에 시각, 날짜, 목적지, 제한 시간을 표시한다.
- [ ] 중복 탭이나 인텐트 재전달로 알람 세션이 중복 생성되지 않는다.
- [ ] 통화, 무음 모드, 방해 금지 모드에서의 정책을 정하고 사용자에게 안내한다.

#### 완료 조건

- 지원하는 Android 버전의 실제 기기에서 예약 시각 오차가 제품 기준 이내이다.
- 화면 잠금, 앱 강제 종료, 절전 모드, 배터리 부족 상태를 포함한 테스트를 통과한다.
- 볼륨과 오디오 포커스 처리 후 다른 앱의 오디오가 정상 상태로 복구된다.

### 5.3 목적지 설정

- [ ] 지도 이동으로 목적지를 지정할 수 있다.
- [ ] 주소 또는 장소명으로 목적지를 검색할 수 있다.
- [ ] 검색 결과를 선택하면 지도와 주소가 갱신된다.
- [ ] 목적지에 짧은 별칭을 지정할 수 있다.
- [ ] 네트워크 오류, 검색 결과 없음, 지도 초기화 실패 상태를 구분해 안내한다.
- [ ] 유효한 좌표가 없는 목적지는 저장하지 않는다.
- [ ] 지도/검색 API 키가 릴리즈 빌드에 올바르게 주입되고 저장소에 노출되지 않는다.

#### 완료 조건

- 한국 내 대표 주소, 건물명, 도로명 검색을 실제 기기에서 확인한다.
- 네트워크가 끊겼다가 복구된 뒤 다시 시도할 수 있다.

### 5.4 도착 미션

- [ ] 알람 해제 시 목적지 도착 미션을 시작한다.
- [ ] 남은 시간, 목적지, 진행 상태를 홈에서 확인할 수 있다.
- [ ] 백그라운드에서도 제한 시간까지 위치를 추적한다.
- [ ] 도착 반경과 위치 정확도를 함께 고려해 도착을 판정한다.
- [ ] 목적지 도착 시 추적을 종료하고 성공 상태를 사용자에게 알린다.
- [ ] 제한 시간 종료 시 마지막 유효 위치로 도착 여부를 재확인한다.
- [ ] 제한 시간 내 미도착 시 정의된 실패 동작을 수행한다.
- [ ] GPS 꺼짐, 위치 권한 회수, 위치 수신 실패 시 사용자에게 복구 방법을 안내한다.
- [ ] 앱 또는 서비스가 재시작되어도 진행 중인 미션을 복원한다.

#### 제품 결정 필요

- [ ] 기본 도착 반경을 확정한다. 현재 코드 기본값은 10m이다.
- [ ] 제한 시간 실패 시 동작을 확정한다.
  - 알람 재울림 여부
  - 재울림 횟수와 간격
  - 사용자가 최종 종료할 수 있는 조건
- [ ] 위치 정확도가 낮을 때 성공 판정을 보류할지, 사용자 확인을 허용할지 정한다.

#### 완료 조건

- 도착, 미도착, GPS 불량, 실내, 네트워크 단절 시나리오를 실제 이동 테스트로 검증한다.
- 미션 종료 후 위치 추적 서비스와 알림이 남지 않는다.
- 동일 미션의 성공과 실패가 동시에 처리되지 않는다.

### 5.5 권한 및 시스템 설정

- [ ] 알림 권한
- [ ] 정확한 알람 권한
- [ ] 위치 권한
- [ ] 위치 서비스 활성화
- [ ] 전체 화면 알림 권한
- [ ] 다른 앱 위에 표시 권한이 실제로 필요한지 재검토하고, 필요하면 목적을 설명한다.
- [ ] 권한 요청 전에 사용 이유를 설명한다.
- [ ] 거부 후 다시 요청하거나 시스템 설정으로 이동하는 경로를 제공한다.
- [ ] 설정 화면에서 현재 권한 상태와 해결 방법을 확인할 수 있다.
- [ ] 권한이 없어도 앱이 종료되지 않고 제한된 기능을 명확히 안내한다.

#### 완료 조건

- 최초 거부, 영구 거부, 설정에서 회수, OS 업데이트 후 변경을 각각 검증한다.
- 권한 허용 전에는 불필요한 위치 추적을 시작하지 않는다.

### 5.6 데이터 저장과 복구

- [ ] 알람 데이터를 앱 내부 저장소에 영속화한다.
- [ ] 앱 재시작 후 알람 목록을 복원한다.
- [ ] 기기 재부팅 후 활성 알람을 재예약한다.
- [ ] 시스템 시각 또는 시간대가 바뀌면 다음 알람을 다시 계산한다.
- [ ] 앱 업데이트 후 기존 알람을 유지한다.
- [ ] 손상된 저장 데이터는 해당 항목만 안전하게 제외하고 사용자에게 영향을 최소화한다.
- [ ] 저장 모델 변경에 대비한 데이터 버전 및 마이그레이션 정책을 추가한다.

#### 완료 조건

- 재부팅, 시간 변경, 시간대 변경, 앱 업데이트 후 중복 또는 누락 예약이 없다.
- 데이터 손상 때문에 앱이 시작 단계에서 종료되지 않는다.

### 5.7 오류 및 예외 처리

- [ ] 사용자 행동으로 해결 가능한 오류는 구체적인 해결 버튼과 함께 표시한다.
- [ ] 네트워크, 지도, 알람 예약, 위치, 알람음 오류를 구분한다.
- [ ] 저장 버튼 연속 탭과 화면 중복 이동을 방지한다.
- [ ] 비정상 종료 이후에도 진행 중인 알람/미션 상태가 복구된다.
- [ ] 릴리즈 환경에서 민감정보가 로그에 기록되지 않는다.
- [ ] 크래시 및 비정상 동작을 확인할 수 있는 모니터링 방식을 정한다.

### 5.8 개인정보 및 보안

- [ ] 개인정보 처리방침을 작성하고 앱 및 스토어에서 접근 가능하게 한다.
- [ ] 위치정보를 언제, 왜, 얼마나 오래 사용하는지 명시한다.
- [ ] 위치정보를 외부 서버에 전송하는지 명확히 표시한다.
- [ ] 지도/검색 제공자와 전달 데이터 범위를 고지한다.
- [ ] 사용하지 않는 권한을 Manifest에서 제거한다.
- [ ] API 키의 플랫폼 제한, 앱 서명 제한, 사용량 제한을 설정한다.
- [ ] 백업 허용 여부를 검토하고 알람/위치 관련 민감 데이터의 백업 정책을 정한다.
- [ ] 앱 삭제 또는 데이터 삭제 시 저장 정보가 제거되는지 확인한다.

## 6. P1 — 출시 권장 기능

P1은 출시 전 구현을 권장하지만, 알려진 제한으로 문서화하고 후속 버전으로 이관할 수 있다.

- [ ] 알람 삭제 취소 또는 실행 취소 메시지
- [ ] 다음 알람까지 남은 시간의 실시간 갱신
- [ ] 알람 예약 완료 피드백
- [ ] 권한 및 배터리 최적화 점검 화면
- [ ] 제조사별 백그라운드 제한 안내
- [ ] 지도 검색 최근 기록 또는 최근 목적지
- [ ] 목적지 도착 반경 설정
- [ ] 알람음 볼륨 미리 확인
- [ ] 빈 화면, 로딩, 오류 화면의 일관된 재시도 동작
- [ ] 글자 크기 확대와 화면 회전 대응
- [ ] TalkBack 콘텐츠 설명과 키보드/스위치 접근성
- [ ] 핵심 화면 분석 이벤트
  - 알람 생성 완료
  - 알람 실행 성공
  - 알람 해제
  - 미션 성공/실패
  - 권한 단계별 이탈

분석 이벤트에는 주소, 좌표, 사용자 지정 목적지 이름 등 위치를 추론할 수 있는 값을 포함하지 않는다.

## 7. P2 — 후속 버전 후보

- 알람 복제
- 공휴일 제외 및 특정 날짜 알람

- 계정과 기기 간 동기화

## 8. 화면별 요구사항

### 홈

- 알람이 없을 때 새 알람 생성 행동을 명확히 제공한다.
- 활성 알람을 우선 표시하되 정렬 기준을 일관되게 유지한다.
- 다음 알람 시각 또는 남은 시간을 표시한다.
- 진행 중인 미션이 있으면 알람 목록보다 높은 우선순위로 노출한다.
- 알람 카드에서 시간, 반복 요일, 목적지, 제한 시간, 활성 상태를 식별할 수 있다.

### 알람 설정

- 신규 생성과 수정 상태를 사용자가 구분할 수 있다.
- 저장하지 않고 나갈 때 변경사항이 있으면 확인한다.
- 시간, 목적지, 제한 시간, 알람음의 유효성을 저장 전에 검사한다.
- 반복 요일이 없는 경우 일회성 알람임을 명확히 표시한다.

### 목적지 선택

- 검색, 지도 이동, 현재 선택 주소, 별칭 입력의 상태가 서로 일치해야 한다.
- 현재 선택할 수 없는 상태에서는 확인 버튼을 비활성화한다.
- 지도 제공자 표기와 이용 조건을 준수한다.

### 알람 울림

- 오조작을 줄이면서도 접근 가능한 크기의 해제 버튼을 제공한다.
- 현재 시각이 아니라 예약된 알람 시각을 명확히 표시한다.
- 알람을 해제하면 목적지 미션이 시작된다는 점을 버튼 문구 또는 보조 문구로 알린다.

### 설정

- 테마를 변경할 수 있다.
- 앱 버전을 확인할 수 있다.
- 권한 상태 및 시스템 설정 이동 기능을 제공한다.
- 개인정보 처리방침, 오픈소스 라이선스, 문의 경로를 제공한다.

## 9. 비기능 요구사항

### 안정성

- 핵심 흐름에서 재현 가능한 크래시 0건
- 같은 알람의 중복 실행 0건
- 재부팅 및 시간 변경 후 예약 누락 0건
- 미션 종료 후 불필요한 위치 추적 0건

### 성능과 배터리

- 앱 시작과 주요 화면 전환에 눈에 띄는 정지 현상이 없어야 한다.
- 지도 화면을 떠나면 불필요한 지도/검색 작업을 중단한다.
- 위치 업데이트 주기와 정확도를 미션 목적에 맞게 제한한다.
- 장시간 포그라운드 서비스 사용 시 배터리 소모를 측정한다.

### 접근성

- 주요 텍스트와 컨트롤은 WCAG AA 수준의 명암을 목표로 한다.
- 터치 영역은 최소 48dp를 권장한다.
- 텍스트 확대 시 핵심 정보와 행동 버튼이 잘리지 않는다.
- 아이콘 단독 버튼에 접근성 이름을 제공한다.
- 색상만으로 활성/오류/성공 상태를 전달하지 않는다.

### 지원 환경

- [ ] 최소 Android 버전을 제품 정책으로 명시한다.
- [ ] 지원 기기 및 화면 크기 범위를 정한다.
- [ ] Samsung, Google 기기를 포함한 실기기 매트릭스를 정한다.
- [ ] 오프라인 또는 불안정한 네트워크에서의 동작 범위를 명시한다.
